# Logy MVP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a lightweight Windows-first Go daemon and CLI that records local development activity and produces searchable offline summaries with optional AI.

**Architecture:** A single Go process owns collectors, event normalization, SQLite persistence, and a named-pipe control endpoint. The CLI reads query data directly from SQLite and uses the pipe only for daemon control. Internal services expose stable query and ingestion interfaces for a future TUI.

**Tech Stack:** Go, SQLite, Windows named pipes, standard library first, table-driven tests, benchmark tests.

**Spec:** `docs/superpowers/specs/2026-08-31-logy-design.md`

## Global Constraints

- Target Windows first; keep package interfaces portable where practical.
- Store data locally; do not send data in background.
- Keep memory under 50 MB in normal operation and CPU nearly idle without events.
- Discover Git projects by finding `.git` directories under configured roots.
- Ignored projects remain ignored across scans.
- Store diffs and transcripts only when explicitly enabled.
- AI runs only from an explicit command and never executes commands.
- Use `apply_patch` for source edits and test every independently useful task.

## File Map

- `go.mod`: module metadata and Go version.
- `cmd/logy/main.go`: CLI entry point and command dispatch.
- `internal/config`: roots, project settings, defaults, and persistence.
- `internal/events`: normalized event types, filters, redaction, and payload rules.
- `internal/store`: SQLite schema, migrations, event writes, and queries.
- `internal/discovery`: `.git` project discovery and ignored-project handling.
- `internal/collectors`: collector interfaces and Git/terminal/filesystem/agent implementations.
- `internal/daemon`: lifecycle, batching, lock, logging, and collector orchestration.
- `internal/control`: Windows named-pipe protocol for daemon control.
- `internal/report`: deterministic summaries and `ask` query interpretation.
- `internal/ai`: opt-in provider interface and sanitized prompt context.
- `docs`: user-facing design and implementation documentation.
